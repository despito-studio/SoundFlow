# Участь у розвитку SoundFlow

SoundFlow розвиває Despito Studio. Ми розглядаємо повідомлення про помилки, пропозиції та зміни коду з урахуванням напрямку продукту й підтримки Windows. Прийняття пропозиції або pull request залишається рішенням команди.

У спілкуванні дотримуйся [правил поведінки](CODE_OF_CONDUCT.md).

## Помилки та пропозиції

Спочатку перевір [наявні Issues](https://github.com/despito-studio/SoundFlow/issues). Для помилки вкажи версію SoundFlow і Windows, кроки відтворення, очікуваний та фактичний результат. Для візуальної проблеми додай знімок екрана, масштаб Windows і розмір вікна. Прибери особисті дані з усіх матеріалів.

Пропозиція має описувати конкретну потребу користувача. Великі зміни інтерфейсу, архітектури, залежностей або платних функцій спочатку обговори в Issue. Для вразливостей використовуй [SECURITY.md](SECURITY.md).

## Робота з кодом

1. Створи гілку від актуальної `main` і внеси зміни в межах однієї задачі.
2. Дотримуйся наявної архітектури та стилю. Для інтерфейсу використовуй спільні компоненти, токени Anicry, геометрію Concentric та каталог AnimateIcons.
3. Перевір змінену поведінку. Для інтерфейсу врахуй масштабування Windows, вузьке вікно, клавіатуру й зменшення руху.
4. Відкрий pull request із поясненням проблеми, результату та виконаних перевірок. Для візуальних змін додай знімки або коротке відео.

Не додавай зібрані програми, особисті профілі, токени, `.env` або локальні інструменти. Зберігай ліцензії та походження сторонніх матеріалів. Версію продукту й релізні теги змінює команда під час підготовки випуску.

## Локальні перевірки

Перед початком налаштуй середовище за [docs/WINDOWS.md](docs/WINDOWS.md). Із кореня репозиторію:

```powershell
. ./scripts/build-windows.ps1 -Action Environment
cargo test --locked --release
```

Для Flutter, коли SDK доступний у `PATH`:

```powershell
cd flutter_app
flutter pub get
flutter analyze
flutter test
```

Перевірки мають відповідати зміні. Для оновлювача також використовуй ізольований сценарій `scripts/test-velopack.ps1`; для інсталятора — перевірки, описані в Windows build. Не тестуй встановлення й оновлення на чужому або робочому профілі.

Текст основної ліцензії Apache 2.0 буде додано власницею проєкту окремо. Сторонні компоненти зберігають свої ліцензійні умови.
